Homomorphic Encryption#

Homomorphic encryption (HE) lets someone compute on data while it stays encrypted. You encrypt x, hand the ciphertext to an untrusted server, the server computes f on it without ever seeing x, and you decrypt the result to get f(x).

This folder is a living research notebook on HE: what it is, how it works mathematically, which schemes exist, and where research stands as of late 2026. It starts as an overview. Each chapter ends with deep-dive candidates: topics to expand into their own documents later.

Status: overview, first pass (2026-10-29).

New to cryptography? Start with the primer#

The chapters below assume you already know what IND-CPA (indistinguishability under chosen-plaintext attack), noise, relinearization and bootstrapping mean. The primer builds all of that up for a reader who knows programming and basic math (modular arithmetic, linear algebra, polynomials, probability) and has used crypto libraries, but has not studied cryptography itself. Every chapter has hand-worked examples, a runnable script in code/primer/ and self-check questions.

The 60-second version#

  1. The idea is old (1978). Rivest, Adleman and Dertouzos asked for "privacy homomorphisms" right after RSA. Textbook RSA is already multiplicatively homomorphic: Enc(a) · Enc(b) = Enc(a · b) (see ../python_rsa). Paillier (1999) is additively homomorphic. Getting both addition and multiplication an unlimited number of times took 31 years.
  2. Gentry (2009) built the first fully homomorphic scheme. His key trick was bootstrapping: homomorphically running the decryption circuit to "refresh" a ciphertext.
  3. Every practical scheme today is built on lattices, specifically the Learning With Errors (LWE) problem and its ring variant RLWE. Ciphertexts carry a small random noise that hides the message. The noise grows with each operation, and bootstrapping resets it.
  4. There are four main scheme families:
    • BGV / BFV: exact integer arithmetic mod t, thousands of values packed per ciphertext.
    • CKKS: approximate real/complex arithmetic, the workhorse for machine learning (ML) and statistics.
    • FHEW / TFHE: bit- or small-integer-level, very fast bootstrapping, arbitrary lookup tables.
    • Matrix FHE (Gentry–Lee, 2025): a newer scheme with native encrypted matrix multiplication.
  5. Performance is the whole story. In 2011 the first implementation needed about 30 minutes for a single bootstrap. Today a TFHE bootstrap takes milliseconds on a CPU core and under 1 ms on a GPU. End-to-end workloads are still about 10²–10⁴× slower than plaintext, depending heavily on the workload and hardware. Prototype ASICs (Intel Heracles, ISSCC 2026) report a further ~1000–5000× over a Xeon on core operations.
  6. It is in production, narrowly. Apple (Live Caller ID Lookup, BFV-based PIR), Microsoft Edge (Password Monitor) and Zama's confidential-token protocol on Ethereum all use it. Frontier-scale private LLM inference under FHE is not practical yet: the best systems are still about 10⁴× slower than plaintext.
  7. It is post-quantum. It rests on the same lattice problems as ML-KEM, the Module-Lattice-Based Key-Encapsulation Mechanism standardized by the National Institute of Standards and Technology (NIST). It is being standardized as ISO/IEC 28033 (parts at Draft International Standard stage in 2026).
